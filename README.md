# prototype-studio

面向产品原型与演示 Demo 的 AI Skill。基于 PRD、产品想法或现有项目，按照 **定布局 → 定视觉 → 做原型** 的流程，制作可交互的前端页面。

支持从零建设和更新原型，聚焦前端展示、模拟数据与演示流程，不默认实现完整后端。

## 快速开始

在支持读取项目文件、编辑代码和运行命令的工作型 Agent 中使用，例如 Codex、Claude Code、Cursor、Windsurf 或 Gemini CLI。把下面这段提示词发给 Agent，让它从 GitHub 仓库安装：

```text
请帮我安装下面这个 Skill：

Skill 名称：prototype-studio
GitHub 仓库地址：https://github.com/chituai/prototype-studio.git

安装完成后，请告诉我是否安装成功，以及我接下来该如何使用它。
```

安装方式和调用语法由各工具决定。安装完成后，可以直接说“使用 prototype-studio”，或在支持 `$Skill` 调用的工具中输入：

```text
使用 $prototype-studio，根据这份 PRD 制作原型。
本轮只实现任务列表、任务详情和新建任务流程，先确认布局。
```

原型项目所需的运行环境和依赖由选定技术栈决定。Skill 会先检查现有工程，再选择适合本轮任务的实现方式。

## 使用模式

| 模式 | 输入 | 执行方式 |
|---|---|---|
| 从零建设 | PRD 或产品想法，可附参考页面、设计规范 | 确定布局和视觉依据，建立规范，搭建可交互原型 |
| 更新原型 | 现有项目与具体修改要求 | 沿用已有技术栈和设计规范，在本轮范围内修改并检查关联影响 |

调整导航、修改布局、新增页面都属于更新。已有布局或视觉依据时跳过相应探索，不要求每次重新走完整流程。需要额外重构时先提出建议，不擅自执行。

### 输入示例

**从零建设**

```text
使用 prototype-studio，做一个团队任务管理 Demo。
本轮演示新建任务、查看详情和修改状态，使用模拟数据。
先用 ASCII 确定首页布局，视觉参考我提供的页面。
```

**更新原型**

```text
使用 prototype-studio 更新当前项目。
将状态筛选移到任务列表顶部，增加“待审核”状态及对应样例。
遵循现有 DESIGN.md，保留搜索、详情和返回行为。
```

## 工作流程

### 1. 定布局

读取相关需求和项目上下文，通过导航树、页面职责与 ASCII 线框确定内容分区、关键入口和跳转关系。新布局确认后再进入视觉实现。

### 2. 定视觉

- 有 `DESIGN.md`、指定参考或认可的历史页面：直接沿用。
- 没有视觉依据：配合 UI Skill，基于同一布局制作三版首页 HTML，选定后扩展。
- 将选定方案的字体、颜色、间距、组件与交互状态落实到 `DESIGN.md`。

视觉设计优先使用用户自己的 UI Skill。也可选用 [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) 或 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)；它们不包含在本项目中，也不会自动安装。

### 3. 做原型

按需选择 HTML、React 或 Next.js，已有项目优先沿用原框架。实现本轮演示路径，复用公共组件，补齐适用状态，再完成代码验证和服务启动。

## 主要能力

| 能力 | 约定 |
|---|---|
| 设计一致性 | 正式原型包含 `DESIGN.md` 和 `AGENTS.md`；新增页面遵循既有规范 |
| 组件复用 | 表格、按钮、选择器、弹窗等重复元素优先抽象或复用 |
| 自定义交互 | 控件及 hover、聚焦、禁用等状态按规范实现，不依赖系统默认外观 |
| Mock 覆盖 | 覆盖各业务状态及适用的空数据、加载、失败、长内容等情况 |
| 完整演示路径 | 操作结果在列表、详情和统计等关联位置保持一致 |
| 重复演示 | 支持恢复初始样例，加载与错误场景可确定性触发 |
| 基本导航 | 支持页面直接打开、刷新、前进与后退 |
| 启动与分享 | 首次可运行后自动启动，按需重启，提供本机及可用的局域网 IP 地址 |
| 版本与交付 | 使用 Git 管理版本，每轮回复列出具体变化、代码位置与验证结果 |

## 范围与限制

- **前端演示优先**：保存、提交、状态流转等通过 Mock 和前端状态模拟，不默认建设数据库、真实鉴权、支付或 AI 服务。
- **PRD 作为输入**：可存放在项目 `docs/prd/` 或沿用原路径；PRD 编写、代码与 PRD 对齐由其他 Skill 承接。
- **代码级验证**：执行适用的类型检查、测试、构建及日志、HTTP 检查，不进行浏览器检查或截图。视觉效果需使用者打开体验。
- **局域网分享**：需要设备处于可互通的网络，且主机与服务保持运行；不包含公网部署或跨设备数据同步。
- **受控更新**：保留已有改动，不随意修改无关功能。Git 提交、推送和分支操作遵循用户授权，不额外维护状态记录或改动日志。


执行规则见 [SKILL.md](SKILL.md)。模板用于生成或补充具体项目的规范，不要求覆盖项目已有文件。
