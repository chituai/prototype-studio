# 项目设计系统

> 模板使用说明：本框架从真实项目设计规范抽象而来。保留结构与约束机制，由项目已认可视觉或选用的 UI Skill 填入实际值；不继承示例项目的名称、浅色风格、字体、配色、尺寸或行业状态。填写完删除说明和填写提示。不适用项明确注明，不凭模板新增业务功能或移动端范围。已有权威规范优先补齐，不强制改写为本模板格式。

## 1. 概览与依据

填写规范名称、版本/阶段、认可来源、适用范围、目标设备和支持主题。说明视觉原则及信息密度，这些原则来自本项目的实际选择。

明确文档职责：本文件定义通用视觉和交互；PRD 定义业务、页面职责与流程；项目维护指南定义组件归属、代码组织和运行方法；Git 管理版本，交付回复说明本轮变化。使用实际链接，避免重复维护同一事实。

页面专属例外记录在产品/页面说明中，并注明范围，不改变全局默认值。设计预览若存在仅辅助理解，不替代规范；无需为完成规范额外截图或建立预览站。

## 2. 设计变量与代码映射

采用三层模型：基础变量（实际颜色/尺度）→ 语义变量（界面用途）→ 组件变量（组件消费规则）。页面和组件引用语义或组件变量，基础变量集中在主题定义中。

| 分组 | 需要填写的内容 |
|---|---|
| 元信息 | 名称、版本、主题、适用范围 |
| colors | 基础色板；文字、表面、边界、操作、焦点和状态的语义映射 |
| typography | 排版角色、字体、字号、字重、行高、字距及设备差异 |
| spacing / sizing | 间距阶梯、页边距、内容宽度、控件与触控尺寸 |
| shapes | 圆角、边框、头像及其他形状的用途映射 |
| elevation / layers | 阴影、遮罩、模糊与层叠顺序 |
| motion | 时长、缓动、减少动态效果策略 |
| components | 变体、尺寸和状态引用的语义变量 |

新建规范默认可用 YAML frontmatter 记录上述结构化值，正文解释用途与约束；已有 JSON/CSS/token 文件时引用其权威路径与映射，不再复制全部数值。说明修改后如何同步文档与代码；除非项目已有工具，不声称 Markdown/YAML 会自动生成 CSS。

最终规范必须有实际值或可解析的权威来源，不能只留下类别列表。复用示例中的三层关系，不复用示例中的具体色值和组件参数。

## 3. 颜色与语义

- 分别定义文字主次、画布与浮层表面、hover/selected 表面、边界强弱、主操作与焦点。
- 对适用的成功、危险、警告和流程状态定义文字、表面、边框组合，并用文案或图标补充语义。
- 品牌色、流程状态、可见范围、通知、分类和方向性数据分别建模，即使同色也不混用含义。行业专属方向色只在有对应需求时加入。
- 写明对比度和可读性目标、适用范围及例外。不可把参考项目的宽松对比度约定自动继承给所有项目。
- 如支持多主题，为每个主题提供完整语义映射，不机械反相；未要求的主题不自动增加。

## 4. 排版

按实际需要列 Display、Title、Panel、Section、Body、Secondary、Caption、Control label、Utility 等角色，并填写：

| 角色 | 字体与回退 | 字重 | 桌面字号/行高 | 窄屏字号/行高（如适用） | 字距 | 用途 |
|---|---|---|---|---|---|---|

定义字体资源及真实可用字重、加载策略、失败回退；不依赖浏览器伪造不存在的字重。数字密集处规定等宽数字、数值与单位的对齐方式。长标题通过换行和空间分配处理，不不断缩小字号。

## 5. 布局与响应式

- 明确间距阶梯、页面 gutter、阅读/应用最大宽度、分区与组件内间距、密度档位。
- 写明目标设备与断点及每档行为；组件根据可用宽度适配，不为每页新增近似断点。
- 明确导航、内容区、固定栏、页面与内部滚动区归属；长内容不能撑破网格。
- 如果支持移动端，定义侧栏折叠、工具栏重排、表格处理、菜单/sheet 转换、触控目标、safe-area、动态视口和软键盘策略，不能只缩小桌面界面。
- 规定内容放大、长文本和字体回退时的布局策略。只支持桌面的项目明确范围，不声称已经支持手机。

## 6. 深度、层级与形状

为静止表面、浮起内容、sticky、菜单、抽屉、模态和反馈层定义适用阴影及层叠顺序。规定遮罩与背景隔离；禁止靠任意巨大 z-index 解决叠层问题。

按组件族定义圆角与允许的尺寸变体。说明边框、留白、阴影的职责，避免每页创造细微不同的半径或深度。具体是否使用阴影、胶囊或直角由认可风格决定。

## 7. 组件规范

每个实际使用的组件都记录：用途与不适用场景、变体、尺寸、语义 token、状态、键盘/触控行为及响应式规则。组件路径与 API 的完整清单放维护指南，本文件只链接必要映射。

### 通用状态约定

覆盖适用的 default、hover、pressed、focus-visible、disabled、loading、selected/expanded、error。非适用状态标明原因，不机械制造状态。hover 与选中可区分；禁用确实禁止操作；加载保持尺寸；错误有说明与恢复方式；焦点清晰可见；状态与 ARIA 同步。

所有产品控件和浮层按规范绘制，不使用系统默认按钮、原生 select 弹层或浏览器 alert/confirm/prompt 代替产品交互；仍保留语义 HTML 和无障碍能力。

### 按钮

按项目定义主操作、次操作、文字、图标及危险动作的变体。列出每档高度、文字/图标大小、内边距、形状与触控范围。明确图标随文字颜色变化、加载宽度、disabled 行为和主要操作层级，不强制继承参考的胶囊形态或 hover 位移。

### 页签、分段与导航

区分路由导航、内容页签、筛选与视图切换，分别采用链接、tab 或 button 的正确语义。规定选中标识、计数、展开状态、键盘移动和窄屏处理，不为了形状相同混用语义。

### 输入与选择

定义输入、复合输入、Select/Combobox、复选、单选、开关及必要日期控件。明确标签、帮助、占位、校验、菜单位置/尺寸、长选项、搜索无结果、清空和禁用。复合输入的聚焦反馈由统一容器承载。规定自定义选择的键盘移动、确认、Esc 和焦点返回。

### 卡片、列表与操作栏

定义可点击与静态卡片、行密度、长标题、标签与数值优先级。整卡点击与内部按钮不得形成嵌套交互冲突；hover 操作有键盘和触控替代。规定固定操作栏出现条件、空间预留与取消后的恢复。

### 表格与数据可视化

定义表头、行高、边界、对齐、排序、筛选、选中和必要固定列。长内容可访问，零值与缺失值区分。按内容选择横向滚动、固定标识列或卡片化，不能任意隐藏关键列。图表规定语义色、图例、单位、空值及可访问的信息替代。

### 状态、徽标与标签

分开描述流程状态、类别、可见范围、未读和可关闭筛选项。给出实际存在的状态映射，不自动引入参考项目的审批或行情状态；不以颜色作为唯一提示。

### 弹窗、抽屉与 sheet

按短确认、复杂表单、详情预览等任务选择容器，明确宽高/最大范围、Header/Body/Footer、内部滚动、关闭按钮、危险确认文案和适用的窄屏转换。

模态层必须处理背景滚动锁、背景不可交互、焦点进入/约束/归还；非模态侧栏不套用模态语义。Esc 只关闭最上层；遮罩是否可关闭按任务定义；关闭事件不穿透到下层。多层弹层由统一机制管理，关闭上层时保留下层应有的锁定。需要外部例外区域时通过组件接口声明，不散落页面补丁。

### 反馈与内容状态

明确 toast、加载、空数据、无筛选结果、错误/重试和成功反馈的布局、文案与恢复路径。骨架屏尽量保持最终布局；关键错误不只靠短暂 toast。Mock 标识及事实/估算/未知表达遵循项目数据约定。

## 8. 图标与动效

定义图标来源、尺寸和线宽，陌生操作提供名称。动效用于反馈或解释空间关系；写明时长与缓动、位移限制和 reduced-motion 替代。是否使用动效及其风格由项目决定，不继承参考的固定曲线或时长。

## 9. 使用规则、验收与变更

列出与本项目视觉决策对应的 Do/Don't，不附加其他项目的审美禁令。

代码级验收覆盖：token 使用、组件变体、状态完整性、键盘/焦点逻辑、Mock 状态、长内容及目标设备的布局规则。组件行为测试使用非浏览器环境。本 Skill 不打开浏览器、不截图，因此实际渲染、设备表现与视觉效果标为待用户体验，不宣称代码检查已经证明这些结果。

更新页面必须沿用既有规范。规范新增项与单页例外分开记录；涉及全局风格或共享默认行为改变，先确认影响范围。不得通过倒改规范为偏离设计的实现背书。
