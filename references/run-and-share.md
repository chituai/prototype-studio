# 启动、重启与局域网分享

目标是让用户拿到能打开的演示入口，而不只是代码文件。执行项目建设或更新时应用本流程；仅讨论方案、编写 Skill 或阅读参考项目时，不启动参考工程。

## 首次启动

1. 读取实际项目运行脚本、锁文件、框架配置和已有维护指南，采用该项目的包管理器与启动方式。先确认脚本是否附带迁移、初始化数据库或外部服务副作用，不为前端演示自动运行这些步骤。
2. 优先复用当前项目已运行且健康的服务；核对进程的工作目录、命令、端口与返回内容，不能仅凭某端口有响应就认为它是本项目。
3. 首次原型可运行后自动启动，无需再询问是否启动。通过环境支持的持久会话或后台进程运行，保留日志和进程标识；不使用会随短命命令结束而消失的运行方式。不自动安装开机启动服务。
4. 按项目配置使用稳定端口。端口被其他项目占用时，不结束对方进程；选择可用端口，记录并告知实际端口。禁止使用宽泛的 killall/pkill 停止所有 Node 或前端进程。
5. 独立 HTML 也可用轻量静态服务器统一提供地址。只服务原型页面及必要资源所在目录，不以整个工作区、用户主目录或包含 PRD/密钥的项目根作为静态公开目录。
6. 用启动日志、监听状态和有超时的 HTTP 请求检查真实入口及必要资源，确认不是启动错误页面。允许这些非浏览器运行检查；不打开浏览器检查、不截图，也不把 HTTP 成功等同于交互或视觉验收。
7. 交付本机地址、局域网地址（可用时）、当前运行状态，以及以后自行启动/停止的具体方式。将真实工作目录、启动命令、端口和日志位置写入已有维护指南，避免只留一句“运行 dev”。不要将临时 PID 当成长期有效的停止指令。

## 修改后自动维护运行状态

- 热更新可正常生效的页面、样式和普通组件修改，不机械重启。
- 修改配置、环境变量或运行依赖，服务退出，或日志表明需重启时，自动重启当前项目服务；先确认进程归属，仅停止对应服务，并等待原端口释放。
- 重启尽量保留端口和入口；如地址变化，在交付中明确给出新地址。重启后再次做非浏览器可用性检查。
- 静态构建预览不会因源码修改自动更新时，先按本轮范围重新构建，再按服务器需要重启或刷新产物；不能把旧页面当成新结果交付。
- 用户明确要求不启动、停止服务或保持离线时遵守要求。因环境或权限无法启动时说明真实原因、可执行的启动方法和缺少条件，不声称已启动。

## 同一局域网访问

- 默认在可分享的本地原型中启用局域网访问；用户指定仅本机时只绑定回环地址。按实际框架版本和项目脚本设置非回环监听地址，例如 0.0.0.0；它是监听设置，不是发给用户的访问地址。
- 从当前主机活动的 Wi-Fi/以太网接口读取实际局域网 IPv4。不要把 localhost、127.0.0.1、0.0.0.0、Docker 网桥或 VPN 隧道地址当成同事可访问地址。
- 多网卡时结合当前路由和接口状态选择；有多个合理候选则标明所属网络，不猜测。没有可用局域网地址时只给本机入口并说明未取得局域网地址。
- 分享链接使用实际协议、IP、端口和页面路径，例如 http://192.168.1.23:5173/demo；示例 IP 不得复制进实际交付。地址变化后重新检测，不长期硬编码某次 IP。
- HTTP 检查本机地址和本机发起的局域网地址请求；这能确认服务监听，但不能证明另一台设备已连通。准确说明另一设备需要同一可互通网络；本机服务和电脑需保持运行。
- 如页面存在本机专属资源或 API/WebSocket 地址，检查是否导致其他设备请求自己的 localhost；优先使用同源相对地址或项目已有可配置基址，改动限定在本次演示需要的范围。
- 如框架有主机/来源限制，只按需要增加实际地址，不关闭全部主机检查或设置任意来源通配。不擅自改防火墙、路由器、端口映射或创建公网隧道。
- 无法跨设备访问时先检查监听地址、端口、IP 与网络隔离，再报告需用户处理的系统设置。服务运行在远程容器或云主机时，不把远端私网地址冒充用户局域网地址；说明环境限制，使用已有授权的端口转发入口或提供本机运行方法。
- 本地存储和内存 Mock 通常各设备独立，分享页面并不意味着多人共享数据；除非另有明确需求，不因此新增同步后端。

## 交付表达

用真实信息替换以下内容，只列已确认可用的入口：

- 已启动 / 已热更新 / 已重启；当前项目及页面入口。
- 本机打开：可点击地址。
- 同一局域网分享：带实际 IP 的可点击地址；说明需要保持电脑与服务运行。
- 后续启动与停止：明确工作目录、实际命令或维护指南链接。
- 已检查服务响应；尚未在另一台设备验证连通性（如确实未验证）。

运行地址与重启情况属于本轮交付信息。运行配置或使用方式改变时更新维护指南，并在交付回复列明；不另外建立改动日志。
