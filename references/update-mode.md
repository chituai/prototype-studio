# 更新原型：基于现有项目的受控修改

本模式用于已有原型的调整。修改导航、重排页面布局、调整信息架构和新增页面均属于更新；不能因变化较大就自动认定重建或重新选型。只有用户明确要求另起项目或整体重新建设时才转建设模式并保留旧版。

## 1. 建立本轮基线

读取相关 AGENTS.md、DESIGN.md、认可页面、组件及当前改动。区分已有未提交内容和本次计划；不能把 Git HEAD 当成唯一基线覆盖用户正在进行的工作。用户指定历史版本时先核对版本与当前差异，不自行执行重置或清理。

简短说明本轮要变什么、哪些相关行为要保留及影响面。小改可在对话中说明，不强制创建计划文件。已有信息足够就执行，不用每次再确认；只有范围或关键依据不明确时提问。

可以在改动前提出有具体依据的重构建议，说明现状问题、收益、影响和必要性。非必需的重构只建议，不阻塞本次修改；额外重构需用户确认后执行，不以建议为由擅自重做。

## 2. 检查影响面

修改前按需查调用与数据流：

- 页面专属样式还是共享 CSS/token？选择器会不会影响其他页面？
- 组件有哪些调用方，默认 props、回调、键盘和焦点约定是什么？
- 路由、查询参数、选中状态、筛选和返回路径是否受影响？
- Mock 是否被其他页面引用，ID、状态枚举及列表/详情关系是否需要保留？

影响范围由依赖决定，不仅由用户提到的文件决定。列出相关的关键行为作为回归对象，不全量检查无关模块。

## 3. 选择最小充分修改

- 局部样式在既有作用域修复；页面特殊需求通过明确的组件变体或参数实现，默认值保持兼容。
- 真正共享的缺陷可以在组件源头修复，同时检查受影响调用方；不为规避共享修改复制一套长期分叉组件。
- 抽取本轮重复元素时保持接口和行为，不顺带迁移所有页面。
- 不修改框架、目录骨架、全局主题或无关依赖，不删除未提及入口、状态、键盘支持或空/错误处理。
- Mock 扩展保留原有场景和稳定 ID；只有用户要求删除的状态才删除，并处理关联处。
- 发现无关缺陷记录并报告，不顺手修。完成任务若必须改变既有结构或接口，说明必要性与影响，先明确扩展范围。
- 缺失 DESIGN.md/AGENTS.md 时依据已认可实现补记真实规则，不将整理文档变成全站改造。

## 4. 代码级回归

按影响选择已有非浏览器测试、类型检查和必要构建。重要共享行为修改或已知易回归路径，在修改前运行相关检查建立基线；简单间距修复无需先跑全套测试。

修改后至少核对：本次预期行为、相关原有行为、共享调用方兼容性、保留的 Mock 状态和数据关联。必要时添加针对实际风险的非浏览器测试；不为每次微调机械增加测试。

对照最终 diff，检查无意删除、全局选择器扩散、公共默认值变化、无关文件修改及测试绕过。不做浏览器检查、截图或浏览器自动化。

失败要区分：已确认原有失败、本次引入、无法确定来源。没有修改前证据时不要猜测“原来就失败”。优先修复本次引入的问题；恢复也只撤销本次有依据的变更，不能覆盖用户改动。

代码修改后按 [启动与局域网分享](run-and-share.md) 保持演示可用：普通变化复用热更新，确需重启时自动重启当前项目，并检查实际入口；如地址变化必须告知用户。

## 5. 交付

逐项列出页面/区域、修改前后、实际代码位置、必要关联调整和验证结果；按 SKILL.md 的改动表在回复中给出具体变化；版本使用 Git 管理，不新增或更新独立状态记录和改动日志。不能说“所有其他功能保证不受影响”；应说清具体检查过哪些行为。仅局部实现变化不重写规范；形成新的通用规则时同步对应文档，PRD 对齐与覆盖矩阵维护交给独立 Skill，本模式不执行。
