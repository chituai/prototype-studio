# 布局与视觉交接

## ASCII 的用途

用导航树和低精度线框说明页面职责、主次信息、内容分区及关键入口，不在此阶段消耗精力设计色彩和装饰。每个分区写具体内容，不用“模块 A”替代业务理解。标出页面与弹层之间的跳转关系。

只覆盖本轮范围。可用“能力 → 页面/入口”短表检查遗漏，不为一个局部任务绘制整套系统。布局确认后不在视觉探索时擅自移动主要分区。

## 视觉依据选择

1. 用户当前指定的依据优先；项目 DESIGN.md 是持续实现的权威来源。
2. 有 DESIGN.md：沿用规范及已有组件，跳过三版探索。
3. 没有 DESIGN.md，但有用户提供或认可的参考/历史页面：直接沿用其视觉，提取规范后实施，不强制探索三版。参考仅用于交互还是也用于视觉，应根据用户描述判断；有实质歧义再问。
4. 若规范与指定参考冲突，列出差异；不要默默混合两套风格。
5. 没有视觉依据：使用用户指定或已安装的适用 UI Skill；多个候选优先采用用户惯用者。都没有时推荐下面两者，由用户选用或提供其他 Skill/视觉依据，不自动安装。

推荐来源：
- [Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)：用于视觉方向与页面设计。
- [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)：用于 UI/UX 设计指导及设计系统探索。

调用时读取实际安装版本，不假设远端和本地内容一致。视觉 Skill 的建议不能擅自改变本轮业务范围、已确认布局或用户禁用浏览器检查的要求。

## 给 UI Skill 的交接内容

- 本轮任务、目标用户与主要操作；相关 PRD 摘要。
- 已确认 ASCII、固定分区和不可修改的导航。
- 用户参考、品牌约束、目标设备及现有组件。
- 统一业务内容与代表性 Mock 数据。
- 需要三版探索还是沿用已有规范；禁止浏览器检查及截图；全部控件按项目视觉实现。

UI Skill 提供视觉方向与表达，原型 Skill 组织 HTML 产物、收集选择、提取规范和扩展实现。不复制 UI Skill 的整套审美规则进入本 Skill。

## 无依据时的三版 HTML

默认放在项目 prototypes/visual-options/ 下，以有辨识度的方案名命名。每版展示相同首页任务、分区和样例；在字体层级、密度、配色、边界和控件表现上有实际区别，不仅换主题色。

使用 HTML/CSS/JS，保持页面能独立打开；关键局部交互可以演示，不提前实现完整系统。提供文件入口和每版差异说明，让用户自行查看，无需截图。

用户选定或要求组合后，保留选择依据。普通细节调整直接执行；组合导致整体视觉不明确时先收敛单一方向。之后提取 DESIGN.md，建立公共样式及组件，不能在框架迁移中重新设计。
