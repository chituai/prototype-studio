# 实现与项目结构

更新任务先执行 [安全更新流程](update-mode.md)，下面的框架选型和目录参考仅适用于新建工程。

## 框架选择

Next.js 是基于 React 的框架，不是与 React 并列的 UI 库。以下是本 Skill 为原型任务设定的默认策略，不是所有生产项目的通用推荐。

按顺序判断：

| 情况 | 默认选择 |
|---|---|
| 已有工程，或用户明确指定栈 | 沿用，不为原型迁移框架 |
| 单页视觉稿、局部演示，无复杂共享状态 | 独立 HTML/CSS/JS |
| 多页面交互、共享组件与本地 Mock，不需要服务端能力 | React + Vite + TypeScript；有路由时采用 React Router |
| 已有或用户指定 Next.js 工程，或演示部署明确需要其渲染方式 | Next.js + TypeScript；新项目默认 App Router，业务流程仍优先本地模拟 |

页面数量多、出现登录外观或“以后可能上线”本身不构成采用 Next.js 的理由；多页 HTML 仍能讲清流程时也不强制框架化。用户没有技术偏好时说明一句选择理由后继续，不要求用户先学习技术栈。

HTML、React + Vite 和 Next.js 在本 Skill 中都优先承担前端 Mock 原型。Next.js 不是自动建设后端的授权；不因登录页、提交按钮或流式聊天外观新增数据库、真实鉴权、支付、消息或 AI 服务。版本沿用项目锁文件；新建时核对官方兼容要求，不在 Skill 中固定易过时的版本号。

事实参考：[React 从零搭建说明](https://react.dev/learn/build-a-react-app-from-scratch)、[Next.js 文档](https://nextjs.org/docs)。

## 目录参考

先读现有工程约定。下面仅用于新项目，按需建立目录，不重排已有项目，也不创建空架子。

```text
prototype/
├── AGENTS.md
├── DESIGN.md
├── docs/
│   ├── prd/                     # 用户或其他 Skill 维护的 PRD，只读输入
│   └── project-guide.md         # 文件归属、样式维护、运行与验证命令
├── prototypes/visual-options/  # 仅实际做过视觉探索时保留
├── public/                     # 本地素材
├── src/
│   ├── app/                    # Vite: 入口、providers、路由配置
│   ├── pages/                  # Vite: 薄页面入口
│   ├── components/
│   │   ├── ui/                 # Button、Select、Dialog、Table 等
│   │   └── layout/             # 导航、页头、整体壳层
│   ├── features/               # 按业务模块组织视图、逻辑与专属组件
│   ├── mocks/                  # 固定样例、场景、状态覆盖说明
│   ├── styles/                 # 语义 token、基础样式、共享样式
│   ├── types/                  # 真正跨模块共享的类型
│   └── lib/                    # 跨模块纯工具；不放页面业务
└── tests/                      # 或沿用邻近测试方式
```

Next.js App Router 使用 src/app/ 下的 layout.tsx、page.tsx 和路由目录替代上述 Vite 入口与 src/pages/；页面入口调用 features，不把全部业务塞入路由文件。交互组件明确客户端边界，Mock 不引入无意义服务端依赖。

独立 HTML 正式原型仍须 AGENTS.md 和 DESIGN.md，可用 pages/、styles/、scripts/、mocks/ 分离内容，不硬套 React 目录。

### 文档与前端分离的项目

若项目同时维护多组资料或多个探索稿，可采用下面结构；单个轻量原型仍用上面的工程根目录结构，不同时建立两套。

```text
project/
├── AGENTS.md
├── DESIGN.md                   # 或引用 docs/design/DESIGN.md
├── docs/
│   ├── prd/                    # 可按模块分组；其他 Skill 负责维护
│   ├── design/                 # 现有设计依据，按需保留
│   └── project-guide.md
├── frontend/                   # package.json、src/或app/、public/等
└── prototype-demo/             # 首页方向稿、单页概念稿；按需保留
```

已有 docs/PRD、docs/prd 或共享设计目录均保留，不为了大小写、命名或本参考而移动文件。业务组件和样式就近放置；跨业务、无业务判断的组件才上移到共享层。api/、stores/、hooks/、packages/ 等按真实复用需求建立，不照抄参考工程的数据库、服务端接口、代码生成器或部署设施。

## 前端演示的实现深度

- 关键路径有真实前端响应：点击保存更新本地列表/详情，筛选改变结果，失败场景可重试；不只弹一个“成功”提示而不改变任何关联展示。
- 固定 Mock 数据加内存状态足够时不引入额外层；需要模拟加载/失败时使用轻量本地异步适配器，不搭建服务端。
- 仅在演示需要刷新保留时使用本地存储，定义重置方式和有效范围；普通临时操作无需持久化。不要存真实敏感数据。
- 登录、权限、提交审核、AI 回答等可以是显式的预设场景；不声称真的认证、投递、运行模型或处理业务。
- 已有真实接口不擅自删除、替换或重构；如当前演示需要离线运行，通过本轮范围内的 Mock 入口隔离。运行检查前查看脚本是否附带数据库迁移或外部副作用，不为前端验证启动这些工作。

## 演示路径与基本导航

- 本轮明确“入口 → 关键操作 → 可见结果”，不制作相互脱节的页面。例如提交表单后，列表出现对应记录，详情显示同一对象，返回保持合理上下文。
- 范围内可点击元素必须有有效反馈；范围外功能可不展示或明确不可用，不留假按钮。此规则不授权补齐全产品。
- 路由页面必须支持直接打开与刷新；实现与部署方式匹配的路由回退。浏览器前进、后退和页内返回保持预期关系，不丢失关键对象或进入空白页。
- 分享所必需的对象 ID、页面或场景放入 URL；临时输入、弹层及无分享需求的状态不强制写入。筛选和选中状态按流程保留或重置，并保持一致。
- 使用代码、非浏览器测试及 HTTP 请求验证路由与状态逻辑，不以这些结果声称浏览器视觉已验收。不强制添加体验指南或演示手册。

## 可重复演示

- 采用稳定的初始样例和确定性场景。同一对象在列表、详情和统计中使用同一数据来源或一致派生；编辑、删除与状态变化同步更新相关展示。
- 提供明确的恢复初始场景方式（按项目选择开发场景入口或重置操作），不强制加入主产品导航。重置只清理本原型的演示数据，不调用 localStorage.clear() 清除同源其他数据。
- 使用持久 Mock 时定义数据版本与不兼容旧数据的恢复策略，避免代码更新后旧缓存破坏演示；无需持久化的原型保持轻量内存状态。
- “今天、最近七天”等相对日期样例使用统一可控的演示时钟或基于启动时间一致生成，避免固定样例随日期过期。真实历史事实不改写成当前数据。
- 加载、错误与重试可重复触发，不依赖随机数或真实外部服务；重置后再次走通同一路径。

## 控件与组件

- 先查现有控件，优先复用或增加语义清楚的变体。本次新增的重复元素默认抽取，不用每次征求许可；更新模式只在本轮相关范围内抽取，保留现有 API 与默认行为，不借机重构其他调用方。
- ui 组件负责可复用呈现与交互；业务状态、字段配置和文案由调用者传入。模块专属组合留在 features 内。
- DESIGN.md 中的语义 token 进入代码的单一来源。组件消费 token，避免每页硬编码不同颜色、边距、圆角和阴影。
- 按钮、输入框保留语义标签，重置系统外观并完整实现规范状态。不能只删除默认 outline 而不提供可见 focus。
- Select/Combobox、日期选择、菜单、Tooltip、Dialog 等需要展示的浮层由项目实现或使用可按规范定制的现有组件。禁止用系统 select 弹层、浏览器 alert/confirm/prompt、原生 title 提示代替产品交互。
- 自定义选择器支持键盘移动、选择、Esc、可见焦点、适当 ARIA 与选中/禁用状态；Dialog 管理焦点进入、约束和关闭后返回。hover 信息不能成为键盘和触控用户唯一入口。
- 无样式交互基础库可以复用；现有组件库要按 DESIGN.md 定制。不得把组件库默认主题当作本项目规范。
- 系统文件选择器等浏览器权限边界不伪造；产品内触发按钮、文件列表和反馈按规范设计。

## Mock 覆盖

实现前从本轮字段和状态定义列出短覆盖表：状态/边界、样例 ID、显示位置或触发方式。在本轮实现与测试中检查；需要持久说明时放在 mocks 附近的简短注释或场景定义中，不新增状态记录或覆盖报告。

| 维度 | 覆盖规则 |
|---|---|
| 离散状态 | 已定义的每种状态至少一个代表样例；三态至少三条记录 |
| 字段边界 | 对会改变展示的长文本、缺失值、零值、大值、多标签等提供代表样例 |
| 页面状态 | 与本轮流程相关的加载、空列表、筛选无结果、错误/重试均可触发 |
| 控件状态 | 适用的选中、禁用、校验错误、提交中等有明确触发路径 |
| 关联关系 | 列表、详情、汇总和跨页跳转使用一致 ID 与数据 |

默认列表尽量同时展示各状态；互斥的页面状态通过开发场景参数或测试夹具确定性切换，并说明进入方式，不把调试控件擅自塞进正式产品导航。缺失值不能显示成零。使用固定场景，不依靠随机生成碰运气；不要求所有字段做笛卡尔积组合。

演示数据明确标注，真实资料保留来源和属性；估算与未知不混淆。不要为填满表格制造真实感事实。

## 最小充分验证

先检查项目现有命令和测试环境，只运行不启动浏览器的检查。HTML 校验语法、脚本与资源引用；框架代码按改动做类型检查、lint 和相关非浏览器测试，路由、配置或跨模块变更增加构建。

新增核心状态交互时验证选择、筛选、返回、重试、键盘及焦点逻辑；对 Mock 枚举覆盖与关联一致性可用纯数据测试，对组件用已有的非浏览器 DOM 测试环境。禁止启动浏览器模式测试、截图或视觉自动验收。

简单样式修复不添加只复述实现的测试。检查代码中系统弹层用法、硬编码 token 和重复组件，但不把字符串扫描当作视觉合规证明。不通过删除测试、放宽类型或屏蔽报错让检查通过。依赖、环境导致无法验证时明确说明。


## 运行入口

首次完成和每次更新后按 [启动与局域网分享](run-and-share.md) 管理服务，主动提供用户能打开的地址。HTTP 运行检查属于非浏览器验证，不代替代码测试或视觉验收。
